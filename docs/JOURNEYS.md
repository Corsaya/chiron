# Journeys and capabilities

Authority: [Workspace standards](../../../../Documents/Obsidian/life-vault/personal-private/Workspace/AGENTS.md), [ownership specification](../../../../Documents/Obsidian/life-vault/personal-private/Workspace/Knowledge%20Architecture.md), and [project decisions](../../../../Documents/Obsidian/pytheas-vault/Architecture/Pytheas%20and%20Chiron%20Project%20Map.md#chiron-reconciliation-decisions--2026-09-14). This code-coupled document grants no new data ownership. Delivery status and gates belong to the [owning roadmap](../../../../Documents/Obsidian/life-vault/personal-private/Workspace/Implementation%20Roadmap.md#chiron-documentation-reconciliation--2026-09-14).

Status: proposed model; first SAT delivery uses minimal journey context. Implements principle 4 in [PHILOSOPHY.md](PHILOSOPHY.md).

These are derived views of existing goals, plans, and skill records, not new registries. A capability graph describes relationships between abilities. A journey map describes a person's paths toward a goal. Journeys reference capabilities; they do not own duplicate versions of them.

Where existing plans define checkpoints, derived views expose their purpose, evidence requirements, and optional target date. Paths may branch, converge, and revisit earlier work. Any checkpoint-completion interpretation must reference supporting evidence and use an owner-approved persistence mapping; it is not an irreversible claim about the person.

For SAT, reference the existing active-attempt plan and skill evidence; introduce no new checkpoint writer until mapped to that owner. Do not build a full interactive map before the session loop works. Assessment criteria are domain-specific and must be versioned before automatically marking checkpoints complete.

Goals may conclude or change. External outcomes such as college admission remain external outcomes; completing a preparation journey does not guarantee them. Aspirations remain optional user-authored context.
