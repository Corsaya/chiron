# Interaction guidelines

Authority: [Workspace standards](../../../../Documents/Obsidian/life-vault/personal-private/Workspace/AGENTS.md), [ownership specification](../../../../Documents/Obsidian/life-vault/personal-private/Workspace/Knowledge%20Architecture.md), and [project decisions](../../../../Documents/Obsidian/pytheas-vault/Architecture/Pytheas%20and%20Chiron%20Project%20Map.md#chiron-reconciliation-decisions--2026-09-14). This code-coupled document grants no new data ownership. Delivery status and gates belong to the [owning roadmap](../../../../Documents/Obsidian/life-vault/personal-private/Workspace/Implementation%20Roadmap.md#chiron-documentation-reconciliation--2026-09-14).

Status: implementation guidance. Supports [PHILOSOPHY.md](PHILOSOPHY.md), especially principles 3, 5, 7, and 8.

- Lead with the next useful action. Keep detail available without making it a prerequisite for starting.
- Use “Suggested” for proposals, “Recorded” for observations, and qualified language for interpretations.
- Explain missing data explicitly. Never render missing evidence as zero performance.
- Distinguish “4 of 6 correct in this session” from a capability estimate.
- Preserve context when opening evidence; closing the inspector returns focus to its trigger.
- Keep response controls labeled and keyboard accessible. Announce save errors and feedback without relying on color or animation.
- Preserve input across recoverable errors and interrupted navigation. Warn before discarding unsaved work.
- Make the source record available as an advanced action; raw Markdown is not the default practice interface.
- Avoid global mastery percentages, unsupported score gains, and statements that a weakness has been eliminated.
- Show meaningful completion without mandatory sound, motion, streak pressure, or identity judgments.

Review the full start-to-completion flow in the running application. Component screenshots alone do not demonstrate a coherent session.
