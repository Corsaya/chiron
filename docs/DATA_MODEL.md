## Source ownership

SAT material, skills, attempts, mistakes, and assessments stay in the existing `learning/Courses/SAT/` structure, physically `learning-vault/Courses/SAT/`. The current course Home identifies the active attempt, library, and assessments; do not hard-code an attempt date. Preserve existing IDs and links. No `Chiron/` record tree or separate session, goal, capability, or mistake registry is introduced.

Goals reference the existing North Star; tasks and projects retain their designated authorities. Health observations remain in existing daily training logs. Calendar events remain provider-owned. These are references in Chiron, not new copies.

## Adapter contract

Expose source identity, path, revision/fingerprint, privacy, record context, and available evidence. Separate recorded observations from derived interpretations and proposed actions. Missing fields remain unknown. Do not impose new required metadata on legacy records or bulk-normalize files. Any additive properties follow Workspace scalar/list conventions.

An interpretation references exact source evidence and the rule version. Corrections supersede prior interpretations without rewriting historical evidence. Durable interpretation/proposal history, interrupted-response persistence, and submission IDs require an explicit mapping into the existing tracking owner before writes are implemented; they do not authorize a new store.

## Write and recovery gate

Inventory the actual tracking guide and current records, map each required field and write target, and document any minimal additive schema in the owning SAT specification before implementing a writer. Preserve unknown fields and prose. Serialize writes, check the source revision, fail on overlapping edits, and use atomic replacement. Retry must not duplicate an attempt or completion.

Derived indexes are optional, rebuildable, and subject to the Workspace search gate. Test permissions, missing data, source round trips, source revision conflicts, duplicate submissions, interrupted work, and recovery against synthetic fixtures. Never copy personal SAT records into code tests or public CI.

## Verified SAT mapping — first read-only slice

The existing active-attempt Tracking Guide specifies `Tracking/attempts.csv` as quantitative authority, with columns `date, session_id, question_id, skill_id, difficulty, correct, confidence, seconds, recognized_5s, fresh_unaided, mode`. The existing `Tracking/skills.json` registry owns skill IDs. Session-template prose owns reasoning and next actions; the Mistake Database owns error annotations. The Mastery Dashboard is generated by the existing `refresh_dashboard.py`, not independently calculated in Chiron.

The course `Home.md` supplies its authored `Next action` and `Evidence we actually have` sections. The first adapter reads those sections with exact source revision and modified time, and offers links to existing materials. It does not execute vault scripts, recompute mastery, infer current calendar availability, or read a hard-coded active-attempt folder. Missing sections are explicit, not fabricated recommendations. Dates in source prose are source claims, not newly verified facts.

Write mapping findings: `(session_id, question_id)` is the existing duplicate key. `correct`, `fresh_unaided`, and `recognized_5s` retain their documented meanings; confidence is recorded before reveal. The CSV has no draft state, recorded answer, source-revision history, or interpretation snapshot fields. Do not invent these fields or a second store. Interrupted-attempt persistence and multi-file correction semantics remain unresolved and block the practice writer, not this read-only view. The session-template-to-CSV manual workflow remains usable.

The generic Classroom localStorage completion flag is not SAT evidence. SAT surfaces suppress its checks and completion counts while leaving other courses and existing browser data intact.
